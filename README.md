# «Ломаем рынок найма»

Локальный лендинг по странице `concept` [этого макета Figma](https://www.figma.com/design/esHeuYwAGf6wLnabEdMiBb/%D0%A1%D0%B0%D0%B9%D1%82-%D0%98%D1%80%D0%B0-%D0%9C%D0%BE%D1%82%D0%BE%D1%80%D0%B8%D0%BD%D0%B0---%D0%9A%D0%B0%D0%B4%D0%BE%D0%BC%D0%B5%D1%86?node-id=1-3). Стек: HTML, CSS, JavaScript, PHP для приёма откликов и Google Apps Script для записи в таблицу. Установка пакетов не нужна.

## Посмотреть локально

```sh
npm run dev
```

Откройте `http://127.0.0.1:4173/`. Без настроенного Apps Script тестовые отклики сохраняются в `.local-submissions/` и не отправляются в Google. Эта папка исключена из Git. Для проверки реальной интеграции локально задайте `APPS_SCRIPT_URL` и `APPS_SCRIPT_SECRET` в окружении перед запуском сервера.

## Подключить Google Таблицу

К таблице привязан проект Apps Script [«FFE — отклики мероприятия»](https://script.google.com/u/0/home/projects/1tOeQyrf8LOEZA8ALagP_4vxkshVImnYL0RbncDKZPG8TSdYzBt-JEPwW/edit). Его исходник — `integrations/google-apps-script/Code.gs`.

1. В редакторе проекта запустите `setupSheet` и разрешите скрипту работать с Google Таблицей и Диском. Он создаст лист «Отклики» с закреплённой шапкой, фильтром и колонками для статуса, оценки и заметок.
2. В **Настройки проекта → Свойства скрипта** задайте `SUBMISSION_SECRET` — длинную случайную строку. Файлы по умолчанию сохраняются в отдельную [папку резюме](https://drive.google.com/drive/u/0/folders/1Uw_sTRm4ZtMEedN6mCegK2S11MCePRmk); при необходимости её можно переопределить свойством `DRIVE_FOLDER_ID`.
3. Опубликуйте скрипт как **Веб-приложение**: запуск от имени владельца, доступ — «Все». URL развертывания заканчивается на `/exec`. Запросы к приложению дополнительно проверяются секретом, который хранится только в свойствах скрипта и в конфигурации сервера.
4. В GitHub Actions secrets задайте `APPS_SCRIPT_SECRET` с тем же значением. При выкладке workflow автоматически создаст `api/config.php` на хостинге. Не добавляйте этот файл в Git. Сервер отправит данные в Apps Script, который добавит строку на лист «Отклики» и сохранит файл резюме на Google Диске.

В листе можно фильтровать участников по статусу и выгружать ответы через **Файл → Скачать → Microsoft Excel (.xlsx)** или CSV. Доступ к таблице «всем по ссылке» оставлен по решению владельца. Прикреплённые файлы резюме сохраняются в его Google Диске; доступ к самим файлам настраивается отдельно.

Форма возвращает успех только после ответа Apps Script об успешной записи. Если интеграция не настроена или запись не удалась, посетитель увидит ошибку и сможет повторить отправку.

## Подготовить для REG.RU

```sh
npm run build
```

Сборка создаст `regru-dist/`: статические файлы, PHP-обработчик и пример конфигурации. Корневой `.htaccess` хостинга не входит в сборку: в нём уже настроено перенаправление на HTTPS. Содержимое папки опубликовано в `/www/ffe-events.ru` на REG.RU. Production workflow создаёт `api/config.php` при наличии секрета и загружает его вместе с сайтом. В хостинге нужны PHP с расширениями `curl` и `fileinfo`, HTTPS, `upload_max_filesize` не меньше 10 МБ и `post_max_size` не меньше 12 МБ. MySQL для этого лендинга не требуется.

Исходники хранятся в [ffe-event-motorina-kadomits](https://github.com/Ilya1999-sys/ffe-event-motorina-kadomits). Workflow `.github/workflows/deploy-regru.yml` собирает сайт и публикует его при каждом push в `main`. Ручной запуск через GitHub Actions по умолчанию работает без загрузки (`dry_run = true`). Перед первым запуском:

1. Создайте в REG.RU отдельного FTP-пользователя с домашней директорией `/www/ffe-events.ru`. Адрес сервера — `server277.hosting.reg.ru`, защищённый FTP (FTPS) работает на порту `21`.
2. В настройках GitHub-репозитория добавьте Actions secrets `REGRU_FTP_USERNAME` и `REGRU_FTP_PASSWORD` для FTP-пользователя, а также `APPS_SCRIPT_SECRET` со значением свойства Apps Script `SUBMISSION_SECRET`. Задайте Actions variable `REGRU_FTP_SERVER_DIR` со значением `/`. Если используете существующего FTP-пользователя с домашней директорией `/`, укажите `/www/ffe-events.ru/`.
3. Запустите workflow вручную с `dry_run = true`, проверьте список файлов, затем повторите с `dry_run = false`. После этого каждый push в `main` будет обновлять сайт.

FTP-пароль, `api/config.php`, `regru-dist/` и личные отклики не добавляйте в Git. Workflow не удаляет сторонние файлы в каталоге сайта, в том числе корневой `.htaccess` и конфигурацию формы.

## Что где лежит

- `site/` — готовая страница и оптимизированные изображения;
- `source-assets/` — оригиналы PNG, выгруженные из Figma;
- `server/` — PHP-обработчик для хостинга;
- `integrations/google-apps-script/` — скрипт записи в Таблицу и загрузки резюме на Диск;
- `scripts/package-regru.mjs` — сборка папки для загрузки.

В макете тексты заданий были перепутаны местами: описание интерфейса стояло под «редакторами», а работа с текстами — под «дизайнерами». На сайте они размещены по соответствующим профессиям. Даты `9–19 ноября` и дедлайн `16 ноября` взяты из макета.

Заголовки используют локально установленный Audex. Перед публикацией проверьте право на использование файла шрифта на сайте и в репозитории.
